# 危险品适用边界与可复核案例

更新：2026-11-18。moon-stow 是三维装载与约束检查库；危险品部分是外部规则及人工复核记录的执行门控。
不提供 IMDG 合规认证、完整危险品数据库或自动拆单建议。原类别矩阵和固定距离映射已移除。

## 证据如何形成结论

| 阶段 | 输入或依据 | 引擎行为 | 能得出的结论 |
| --- | --- | --- | --- |
| 声明 | 每件货的类别、UN 编号、包装类别、确切声明/SDS 版本引用 | 格式错误报 `HazardInputInvalid`；危险品缺声明引用则暂停 | 输入格式有误或缺资料；不证明货物分类真实 |
| 组合关系 | 调用方提供的两个完整声明、规则编号、来源、关系 | 双向精确匹配，检查所有涉及危险品的组合；未知报 `HazardRuleUnknown` | 尚不能规划；不能将未命中解释为相容 |
| 明确禁配 | `ProhibitSameUnit` | 整单暂停，报 `HazardSameUnitForbidden` | 当前提供的规则禁止同载具；位置、间距和复核记录均不能覆盖 |
| 外部人工复核 | 载具、完整货单与组合规则快照；记录编号、复核人、外部证据引用 | 缺记录、字段空缺或快照变化报 `HazardReviewRequired` | 当前货单尚不具备几何规划所需记录 |
| 几何规划 | 所有组合已有规则、无禁配，且整单复核记录匹配 | 按尺寸、载重、支撑等条件规划；始终带 `HazardPlanningOnly` 警示 | 仅在给定声明和规则下计算几何，运输放行仍由外部负责 |

`pack` 与 `palletize` 在整单评估有错误时返回零放置、完整 `unplaced` 和原因；
`pack_all` 返回 `None`。`verify` 即使收到空布局，也评估完整货单，不能靠删放置项隐去禁配。
`cartonize` 暂不对危险品自动选箱，因为改变箱型或拆成子单会改变复核范围。

## 案例一：同为第 8 类，具体物质仍禁配

演示货物 A：盐酸水溶液 30%，声明 UN1789、第 8 类、PG II、20 kg。
演示货物 B：次氯酸钠溶液、有效氯 12%，声明 UN1791、第 8 类、PG III、20 kg。
两件均假设为 600×400×400 mm 包装，声明/SDS 引用为 DEMO 数据。
这些是测试声明，未取得真实 SDS 或包装证明，不能拿来给实际货物定类。

[ICSC 1119](https://www.inchem.org/documents/icsc/icsc/eics1119.htm) 的适用对象为有效氯 >10% 的次氯酸钠溶液，
其 Chemical Dangers 描述遇酸分解并产生包括氯气在内的有毒腐蚀性气体。
调用方据此制定 `LOCAL-ACID-HYPOCHLORITE-1` 企业策略，关系为 `ProhibitSameUnit`。
该来源支持化学不相容风险与企业策略，不能直接等同于 IMDG 对某一航次的法定禁同柜条款。

两件类别均为 8；旧类别矩阵会漏掉具体物质关系。新流程匹配完整声明和明确规则，
整单输出禁配原因，不摆入任一件，也不自动生成两票可承运子单。
测试把两件手工摆到相隔 9.4 m 的位置后再 `verify`，禁配仍然存在。
现场复核人应确认物质身份、浓度与声明，保持禁同柜策略；如需改成两个货单，
须为每个新单分别完成包装、CTU、航线与承运人等复核，不能继承旧单的结论。

## 案例二：找不到组合规则

去掉上述策略，或者把声明引用从 SDS-r1 改成 SDS-r2，产生 `HazardRuleUnknown`。
人工记录的存在不能补齐未知关系；须先查明适用关系，形成带来源的具体规则并重新复核。
同一种 UN 编号、相同类别、与普通货相邻，都不会自动被视为兼容。

## 案例三：复核完成后仅计算几何

示例改为只含上述盐酸的一份货单。没有组合不等于没有危险品运输条件：仍须外部复核。
示例构造 `DEMO-REVIEW-1`，演示“已完成外部复核”的程序状态，随后可放置一件，
并在输出中持续保留 `dangerous-goods-geometry-only` 和运输批准由外部负责的警示。
该记录明确为虚构，没有真实复核人签署或承运人批准，不证明这个盐酸包装实际可运输。

实际应用的复核记录应包含下列内容的版本、日期、检查结果与条件，而不是一句“已审核”：

1. 发货人声明、SDS 第 2/7/10/14 节与实际物质/浓度/副危险性是否一致，包装类别和数量是否确认。
2. 当前适用 IMDG 版本、危险货物一览表条目、适用特殊规定/隔离组与具体物质关系；逐项记录依据。
3. 同柜/同运输组件的条件、包装和装载限制、CTU 类型与状态、航线/船舶/舱面条件及承运人要求。
4. 哪些条件已确认，哪些未解决；未解决则不创建允许规划的记录。记录编号、复核人、日期、证据位置和失效条件。

[IMO 页面](https://www.imo.org/en/publications/Pages/IMDG%20Code.aspx) 当前说明 2024 Edition、Amendment 42-24 自 2026-01-01 强制适用。
本次只核读公开版本说明，未核验完整规范、DGL 或全部特定条款，不能声称实现上述法规检查。

## API 使用与信任边界

`Hazard::with_declaration` 绑定的字符串应指向不可变版本资料，涵盖物质名称、成分、浓度、
副危险性、包装、数量等。引擎不解析这些资料，也不核验签名、复核资质、时间有效期或承运人批准。
资料内容、航线或运输条件发生变化时，调用方须更换引用并重新复核；库不能发现引用外的变更。
示例正向分支仅证明程序门控能够工作，不证明真实外部审核已经完成。

通过 `StowRules.hazard_pairs` 提供 `HazardPairRule` 数组，再用
`HazardReview::new(unit, cargos, pairs, record_id, reviewer, evidence)` 构造允许几何规划的记录，
设置到 `StowRules.hazard_review`。拒绝或待核查时不要创建该记录。
规则数组和复核记录的任何公共入口都不是安全认证边界；本库信任调用方提供的事实，不能防伪。
详见完整可运行的 `examples/hazard/main.mbt` 与 `hazard_scenarios.mbt`。

类别/UN/包装类别没有物质数据库交叉校验；爆炸品未细分项别/配装组，缺副危险性等结构化法规字段。
`HazardClass::parse` 返回可选类别；无法识别就拒绝处理。`hazard` 完全省略则仍属于调用方的普通货声明，
本库不会根据货名识别误报或漏报危险品。格式有效不代表分类正确。
`1789` 与 `UN1789` 均可输入，但规则匹配按完整值，调用方应统一编号写法；不匹配时暂停。

`is_clear` 仅表示没有错误；`pack_all` 的 `Some` 仅表示当前规则下几何整单完成。
JSON 输出与 CSV 行含 `planning_scope`；文本、Markdown 的危险品诊断含复核编号/证据；
送货清单与 SVG 标明范围。CSV 是坐标表，须同时保留完整诊断及外部审核记录，不作为出运批准。

## 复现

```bash
moon test --deny-warn
moon run examples/hazard
```

测试覆盖禁配、未知、正向几何规划、非法声明、重复货号、失效复核、相反规则、
未放置货物检查、码垛/选箱旁路以及导出范围标识；它们是软件行为证据，不是危险品合规验收。
